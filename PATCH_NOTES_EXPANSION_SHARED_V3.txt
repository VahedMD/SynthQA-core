WHAT WAS FIXED

1. Resume after an empty first checkpoint
   - The initial smoke test correctly excluded 1THB143 after all four shared-v3
     top-ranked dose profiles failed the existing dose-profile validity rule.
   - With zero accepted cases, the old script wrote a newline-only results CSV.
     pandas.read_csv then raised EmptyDataError on the next run.
   - The revised script safely reads empty checkpoints and removes schema-less
     empty CSVs rather than creating an invalid resume file.

2. Correct cohort disjointness
   - The old candidate-order builder reserved the nominal stratified candidates,
     not the actual frozen 12-patient stratified cohort.
   - This allowed 1THB052 to enter the expansion candidate order even though it
     belongs to the executed stratified cohort.
   - The revised script reads scripts/stratified_candidate_patient_ids.txt,
     validates that it contains exactly 12 unique IDs, and excludes those IDs,
     the fixed 11-patient PB comparison cohort, and the explicit 1THB121 hold-out.
   - The existing seeded candidate order is retained in its original relative
     order; only reserved IDs are removed and candidate ranks are compacted.
   - The supplied candidate-order CSV has already been repaired. It now has
     61 candidates, starts with 1THB143, and has no overlap with any reserved set.

3. Safer checkpoint recovery
   - Patients already present in the results checkpoint are treated as completed
     even if a process stopped before writing the corresponding processing log.
   - Shared-R80 evaluation failures are written to the processing log rather
     than terminating the entire cohort run.
   - Invalid dose-profile attempts now record peak index, peak dose, distal
     minimum, and distal-minimum/peak ratio for diagnosis.
   - Summary JSON generation handles non-finite values safely.

WHAT WAS NOT CHANGED

- Candidate preselection is still the exact _plan_candidate_records function
